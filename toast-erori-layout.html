1 · Mesaje scurte

Toast

Anunțuri
Anunț salvat!

Toast-ul apare jos pe ecran și dispare singur după 2–3 secunde. Utilizatorul nu trebuie să apese nimic.

Linia care îl face 
Toast.makeText(this, "Anunț salvat!", Toast.LENGTH_SHORT).show();

Ai nevoie de import android.widget.Toast; sus în fișier. Dacă Toast e roșu, apeși Alt+Enter și ți-l adaugă Android Studio.

BucataCe faceCe pui acolo
Toast.makeText(…)creează toast-ul, dar încă nu-l afișează–
thiscontextul: activitatea în care eștithis, MainActivity.this sau context (vezi mai jos)
mesajultextul afișat, un String"Importate: " + importate.size()
duratacât stă pe ecranToast.LENGTH_SHORT (~2 s) sau Toast.LENGTH_LONG (~3,5 s)
.show()îl afișeazăobligatoriu: fără el nu apare nimic
Unde îl apelezi

Oriunde în codul activității care chiar rulează. Cele patru locuri din proiect:

// 1. la pornirea ecranului: în onCreate, după setContentView (MainActivity)
int ultimaIncarcare = PreferinteService.citesteNrIncarcate(getPrefs());
Toast.makeText(this, "Ultima încărcare: " + ultimaIncarcare, Toast.LENGTH_LONG).show();

// 2. la click pe un buton
binding.btnSalveaza.setOnClickListener(v -> {
    Toast.makeText(this, "Ai apăsat Salvează", Toast.LENGTH_SHORT).show();
});

// 3. după o acțiune: la finalul lui importa() (MainActivity)
Toast.makeText(this, "Importate: " + importate.size(), Toast.LENGTH_SHORT).show();

// 4. într-un catch, ca să spui că ceva n-a mers (MainActivity, meniul de import)
catch (Exception e) {
    Toast.makeText(this, "Eroare la import: " + e.getMessage(), Toast.LENGTH_LONG).show();
}
Ce pui la context
Unde scrii Toast-ulPrimul argumentDe ce
direct în activitate sau într-o lambda v -> { … }thisthis e chiar activitatea
într-o clasă anonimă new View.OnClickListener() { … }MainActivity.thisacolo this e listener-ul, nu activitatea
în adapter sau în altă clasă care nu e activitatecontextcâmpul primit în constructor (în AnuntAdapter se cheamă context)
Capcană: număr gol în loc de text 
Toast.makeText(this, anunturi.size(), Toast.LENGTH_SHORT).show();           // CRAPĂ
Toast.makeText(this, "Total: " + anunturi.size(), Toast.LENGTH_SHORT).show(); // OK

Compilează, dar crapă când rulează. Un int gol e luat drept id de resursă (R.string.ceva), iar resursa nu există, așa că primești Resources$NotFoundException. Lipește mereu numărul de un text.

2 · Erori, felul A

Erori pe câmpuri: setError

Anunț nou
Titlu!
Titlul este obligatoriu
Laptop folosit, stare bună
1200

Câmpul primește un „!” roșu la capăt. Când dai click pe el, apare balonul cu mesajul.

Cum o pui și cum o ștergi 
binding.etTitlu.setError("Titlul este obligatoriu"); // pune eroarea
binding.etTitlu.setError(null);                       // o șterge

setError există pe EditText (și pe TextView). Spinner-ul și CheckBox-ul nu au setError: pentru ele folosești un Toast.

Unde o apelezi: în metoda butonului de salvare, mereu în ordinea asta
  1. Citești textul din câmpuri: binding.etTitlu.getText().toString().
  2. Verifici fiecare câmp.
  3. Pui setError pe câmpurile greșite.
  4. Dacă e vreo eroare: return; și te oprești aici.
  5. Altfel construiești obiectul, apoi putExtra, setResult, finish.

Varianta simplă, fără validator separat

private void salveaza() {
    String titlu = binding.etTitlu.getText().toString();
    String pretText = binding.etPret.getText().toString();
    boolean ok = true;

    if (titlu.trim().isEmpty()) {
        binding.etTitlu.setError("Titlul este obligatoriu");
        ok = false;
    }

    try {
        double pret = Double.parseDouble(pretText);
        if (pret <= 0) {
            binding.etPret.setError("Prețul trebuie să fie mai mare ca 0");
            ok = false;
        }
    } catch (NumberFormatException e) {
        binding.etPret.setError("Preț invalid");
        ok = false;
    }

    if (!ok) return;   // NU mergi mai departe
    // ... aici construiești Anunt-ul
}

Folosești variabila ok în loc de return la prima eroare ca să apară erorile pe toate câmpurile deodată, nu pe rând.

Varianta din proiect (AddActivity + FormularValidator)

FormularValidator.erori(...) verifică tot și întoarce un Map: cheia e numele câmpului, valoarea e mesajul. Câmpurile corecte nu apar deloc în map.

Map<String, String> erori = FormularValidator.erori(titlu, descriere,
        pretText, cantitateText, categorieText, dataText);

// erori.get("titlu") dă mesajul, sau null dacă titlul e bun.
// setError(null) șterge eroarea veche, deci o linie face ambele.
binding.etTitlu.setError(erori.get("titlu"));
binding.etDescriere.setError(erori.get("descriere"));
binding.etPret.setError(erori.get("pret"));
binding.etCantitate.setError(erori.get("cantitate"));
binding.etData.setError(erori.get("data"));

if (erori.containsKey("categorie")) {
    // Spinner-ul nu are setError, așa că anunțăm prin Toast
    Toast.makeText(this, erori.get("categorie"), Toast.LENGTH_SHORT).show();
}
if (!erori.isEmpty()) {
    return; // NU continuăm dacă există erori
}
2 · Erori, felul B

Erori care crapă aplicația: try/catch

Unele apeluri „aruncă” o excepție când primesc ceva greșit. Dacă nu o prinzi, aplicația se închide cu „App keeps stopping”. Le pui în try/catch.

ApelulCând crapăExcepția
Double.parseDouble, Integer.parseInttextul nu e număr (gol, „abc”)NumberFormatException
LocalDate.parsedata nu e de forma AAAA-LL-ZZDateTimeParseException
Categorie.valueOftextul nu e o valoare din enumIllegalArgumentException
citirea unui fișier din assetsfișierul nu existăIOException
parsarea de JSON / XMLtextul e stricat sau lipsește o cheieJSONException, Exception
Forma 
try {
    // codul riscant
} catch (Exception e) {
    // ce faci dacă a crăpat
}

catch (Exception e) prinde orice. e.getMessage() îți dă textul erorii.

În proiect: meniul de import (MainActivity) 
try {
    String text = citesteAsset("anunturi.json");
    importa(ParserJson.dinText(text));
} catch (Exception e) {
    Toast.makeText(this, "Eroare la import: "
            + e.getMessage(), Toast.LENGTH_LONG).show();
}
Cele două feluri, împreună (FormularValidator)

Validatorul folosește try/catch ca să transforme o excepție într-un mesaj de eroare pentru câmp, în loc să lase aplicația să crape:

try {
    double pret = Double.parseDouble(pretText.trim());
    if (pret <= 0) {
        erori.put("pret", "Pretul trebuie sa fie mai mare ca 0");
    }
} catch (NullPointerException | NumberFormatException e) {
    erori.put("pret", "Pretul trebuie sa fie un numar (ex. 10.5)");
}
Bonus: erori doar pentru tine

Log.e("DAM", "ceva n-a mers", e); scrie eroarea în Logcat, tab-ul de jos din Android Studio. Utilizatorul nu vede nimic; tu vezi tot mesajul și linia unde a crăpat. Tot în Logcat vezi și de ce s-a închis aplicația când n-ai pus try/catch.

3 · Cum arată ecranul

Layout-uri

Un layout e un fișier XML din res/layout/ care spune cum arată ecranul. Codul Java spune ce face ecranul.

Legătura cu activitatea
activity_add.xmlîl scrii tu
→
ActivityAddBindinggenerat automat, cu un câmp pentru fiecare id
→
AddActivity.onCreateîl încarcă și îl pune pe ecran
binding = ActivityAddBinding.inflate(getLayoutInflater());
setContentView(binding.getRoot());

Numele fișierului are doar litere mici, cifre și _: activity_add.xml merge, ActivityAdd.xml nu.

Cum arată un layout: un container cu componente în el 
<LinearLayout xmlns:android="http://schemas.android.com/apk/res/android"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="vertical"
    android:padding="16dp">

    <EditText
        android:id="@+id/etTitlu"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:hint="Titlu"
        android:inputType="text" />

    <Button
        android:id="@+id/btnSalveaza"
        android:layout_width="match_parent"
        android:layout_height="wrap_content"
        android:text="Salvează" />
</LinearLayout>
Atributele care contează
AtributCe face
layout_width, layout_heightobligatorii la orice element. match_parent = cât părintele, wrap_content = cât conținutul, sau o valoare fixă ca 100dp
android:id="@+id/etTitlu"numele prin care ajungi la element din Java: binding.etTitlu. Fără id nu-l poți accesa
orientationvertical (unul sub altul) sau horizontal (unul lângă altul); doar la LinearLayout
text, hinttextul afișat / textul gri care apare când câmpul e gol
inputTypece tastatură apare: text, textMultiLine, number, numberDecimal, textEmailAddress, textPassword
padding, layout_margin, textSizespațiu înăuntru / spațiu în afară, în dp; mărimea textului, în sp
Containere
  • LinearLayout: pune elementele unul sub altul (sau unul lângă altul). E cel mai simplu; pe ăsta îl folosești la examen.
  • ScrollView: pentru ecranele care nu încap. Poate avea un singur copil, deci pui un LinearLayout în el, cum e în activity_add.xml.
  • ConstraintLayout: îl pune wizard-ul implicit. E mai greu, pentru că fiecare element are nevoie de constrângeri ca să știe unde stă.
Ce apelezi din Java pe fiecare componentă
În XMLÎn Java (prin binding)
TextViewbinding.tvCurs.setText("1 EUR = 4.97 RON");
EditTextgetText().toString(), setText(…), setError(…)
Buttonbinding.btnSalveaza.setOnClickListener(v -> salveaza());
CheckBoxbinding.chkNou.isChecked()
SpinnersetAdapter(…), getSelectedItem()
ListViewbinding.lvAnunturi.setAdapter(adapter);
Cum creezi un layout
  • Automat, odată cu activitatea (New → Activity → Empty Views Activity, cu Source Language: Java).
  • Manual: click dreapta pe res/layout → New → Layout Resource File → scrii numele (de exemplu activity_muie) → Root element: LinearLayout → OK.
Cum îl vezi
  • Deschizi fișierul XML. Sus în dreapta ai butoanele Code, Split, Design.
  • Split îți arată codul și desenul ecranului unul lângă altul. Mai multe în ghidul Proba 3.
item_anunt.xml e alt fel de layout

Nu e pentru tot ecranul, e pentru un singur rând din listă. Nu-l încarci cu setContentView; îl încarcă adapterul pentru fiecare rând, iar elementele le iei cu findViewById:

convertView = LayoutInflater.from(context).inflate(R.layout.item_anunt, parent, false);
holder.tvTitlu = convertView.findViewById(R.id.tvTitlu);

De reținut din layout

Pasul 2 · Activitatea

Ce face ecranul

java/ro/ase/dam/examen/CalculActivity.java
Ce faci
  1. Click dreapta pe pachetul ro.ase.dam.examen → New → Java Class → CalculActivity → Enter.
  2. Ștergi ce a pus Android Studio și lipești codul de mai jos.
package ro.ase.dam.examen;

import android.os.Bundle;
import android.widget.Toast;
import androidx.appcompat.app.AppCompatActivity;
import ro.ase.dam.examen.databinding.ActivityCalculBinding;

public class CalculActivity extends AppCompatActivity {

    // 1. Legătura cu activity_calcul.xml (clasa e generată automat din numele fișierului)
    private ActivityCalculBinding binding;

    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);

        // 2. Încarci layout-ul și îl pui pe ecran
        binding = ActivityCalculBinding.inflate(getLayoutInflater());
        setContentView(binding.getRoot());

        // 3. TOAST la pornirea ecranului
        Toast.makeText(this, "Completează prețul și cantitatea", Toast.LENGTH_SHORT).show();

        // 4. Legi fiecare buton de metoda lui
        binding.btnCalculeaza.setOnClickListener(v -> calculeaza());
        binding.btnGoleste.setOnClickListener(v -> goleste());
    }

    private void calculeaza() {
        // a. Citești textul din fiecare câmp
        String produs = binding.etProdus.getText().toString().trim();
        String pretText = binding.etPret.getText().toString().trim();
        String cantitateText = binding.etCantitate.getText().toString().trim();

        boolean ok = true;   // devine false la prima eroare, dar verificăm tot
        double pret = 0;
        int cantitate = 0;

        // b. Verifici fiecare câmp și pui EROAREA pe el (setError)
        if (produs.isEmpty()) {
            binding.etProdus.setError("Scrie numele produsului");
            ok = false;
        }

        // parseDouble CRAPĂ dacă textul nu e număr -> îl prinzi cu try/catch
        try {
            pret = Double.parseDouble(pretText);
            if (pret <= 0) {
                binding.etPret.setError("Prețul trebuie să fie mai mare ca 0");
                ok = false;
            }
        } catch (NumberFormatException e) {
            binding.etPret.setError("Scrie un număr, de exemplu 12.5");
            ok = false;
        }

        try {
            cantitate = Integer.parseInt(cantitateText);
            if (cantitate < 1 || cantitate > 100) {
                binding.etCantitate.setError("Cantitatea trebuie să fie între 1 și 100");
                ok = false;
            }
        } catch (NumberFormatException e) {
            binding.etCantitate.setError("Scrie un număr întreg");
            ok = false;
        }

        // c. Dacă e vreo eroare: Toast + te oprești
        if (!ok) {
            Toast.makeText(this, "Corectează câmpurile marcate cu roșu", Toast.LENGTH_SHORT).show();
            return;
        }

        // d. Totul e corect: calculezi și afișezi
        double total = pret * cantitate;
        if (binding.chkReducere.isChecked()) {
            total = total * 0.9;
        }
        // String.format("%.2f", ...) = două zecimale
        binding.tvRezultat.setText("Total pentru " + produs + ": "
                + String.format("%.2f", total) + " lei");
        Toast.makeText(this, "Gata, am calculat!", Toast.LENGTH_SHORT).show();
    }

    private void goleste() {
        // setText("") golește câmpul
        binding.etProdus.setText("");
        binding.etPret.setText("");
        binding.etCantitate.setText("");

        // setError(null) șterge erorile rămase de la ultimul calcul
        binding.etProdus.setError(null);
        binding.etPret.setError(null);
        binding.etCantitate.setError(null);

        binding.chkReducere.setChecked(false);
        binding.tvRezultat.setText("Total: -");
        Toast.makeText(this, "Am golit formularul", Toast.LENGTH_SHORT).show();
    }
}

Laptop, preț 0, cantitate 3„!” doar pe preț: „Prețul trebuie să fie mai mare ca 0”

De ce e nevoie de try/catch aici

Dacă lași prețul gol, Double.parseDouble("") aruncă NumberFormatException. Fără try/catch aplicația s-ar închide; cu el, prinzi excepția și pui un setError pe câmp.

// Citeste un asset text, util pentru TODO 10.
private String citesteAsset(String nume) throws Exception {
    try (java.io.InputStream in = getAssets().open(nume);
         java.io.ByteArrayOutputStream out = new java.io.ByteArrayOutputStream()) {
        byte[] buffer = new byte[4096];
        int n;
        while ((n = in.read(buffer)) != -1) out.write(buffer, 0, n);
        return out.toString("UTF-8");
    }
}

Ce crapă cel mai des

Capcane

  • Am pus .show() la fiecare Toast.
  • Nu dau niciun int gol lui Toast.makeText sau lui setText: scriu "" + n sau String.valueOf(n).
  • După setError am return; dacă există erori; altfel obiectul se creează cu date greșite și crapă la parseDouble.
  • Orice parseDouble, parseInt, LocalDate.parse sau citire de fișier e în try/catch (sau trece întâi prin validator).
  • Fiecare element din XML are layout_width și layout_height.
  • Id-ul din XML e scris la fel ca în Java. Dacă binding.etX rămâne roșu, dau Build → Rebuild Project.
